The first line admits every pod to port 8080 of the listener, so that a default-deny of the
namespace (networkPolicy.namespaceDefaultDeny, or one of your own) does not refuse it. "control"
dials the listener from a pod the egress policy does not select, "private" from the rebom pod.
Each is printed once per address of the listener: one on a single-stack cluster, an IPv4 and an
IPv6 one on a dual-stack cluster. Read the pair of each address:
  control exit=0, private exit=1 for EVERY address: ENFORCED. The listener answers a plain pod
    and rebom is refused, in each address family the cluster has.
  private exit=0 for any address: NOT enforced for that family, whatever the control prints; or
    the pod range of that family is missing from
    networkPolicy.rebomBackend.egress.public.extraExcept (IPv4: a public-looking range; IPv6:
    any range, see README.md); or a rule of extraEgress or another policy of yours allows it.
  control exit=1, private exit=1 for an address: proves NOTHING for that family. The listener
    is unreachable for another reason, so the refusal says nothing about egress. Repeat the
    control line after a few seconds; if it stays exit=1, see "Check that it is enforced" in
    the chart's README.md (helm show readme).
{{- if not .Values.use_external_postgres }}
  database exit=0, public exit=0: DNS, the database and a public address work.
{{- else }}
  public exit=0: DNS and a public address work.
{{- end }}
    public exit=1 is expected without a public IPv4 rule on port 443 (public.ipFamilies without
    IPv4, public.ports) and on a cluster with no direct route to the internet. If no line
    prints exit=0, nc may not work in the rebom container, and private exit=1 proves nothing
    either.
